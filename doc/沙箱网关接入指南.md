# Lazyx Sandbox Gateway V0 接入指南

## 它解决什么问题

Gateway 把“Agent 想执行什么”和“具体使用 AGSX/PPIO 的密钥、SDK、清理逻辑”隔开：

```text
其他 Agent
   │  Bearer API Key
   ▼
Sandbox Gateway
   ├─ 鉴权：tenant / agent / allowed_tasks
   ├─ 策略：任务类型、文件路径、网络档位、Provider 能力
   ├─ 编排：创建 → 上传 → 执行 → 下载 Artifact → Receipt → 销毁
   └─ Provider Adapter：Tencent AGSX / PPIO
```

Agent 不需要持有云厂商密钥，也不需要直接理解 AGSX/PPIO 的 SDK。

当前自动路由规则是：通用 Code 优先 PPIO、经营表格固定优先 AGSX、Browser 按已配置
能力选择；失败后不会自动跨 Provider 重放，避免重复执行和重复计费。经营表格走 AGSX
不等于已经证明网络隔离，真实 VPC/出网策略仍需专项验证。

## V0 对外能力

| 能力 | HTTP | Python SDK | 说明 |
| --- | --- | --- | --- |
| 执行代码 | `POST /v1/executions` | `execute_code()` | Python/JavaScript，支持输入文件和输出 Artifact |
| 上传文件 | `POST /v1/files` | `upload_file()` | V0 使用 JSON + Base64，单文件上限默认 10 MiB |
| 下载 Artifact | `GET /v1/executions/{id}/artifacts/{name}` | `download_artifact()` | 只允许下载该执行产生的 Artifact |
| 通用表格分析 | `POST /v1/executions` | `analyze_spreadsheet_file()` | CSV/XLSX → 结构、质量、统计、异常、图表、Receipt |
| 经营简报 | `POST /v1/executions` | `analyze_spreadsheet_file(..., generate_briefing=True)` | 在同一分析结果上追加 Markdown、PDF、PPTX |
| 公开网页 | `POST /v1/executions` | `browse_public_page()` | 只读公开 HTTP(S)，正文视为不可信观察数据 |
| 查询/取消 | `GET` / `POST .../cancel` | `get_execution()` / `cancel()` | 状态和回执可审计 |

## 本地启动

先准备 `.env` 中至少一个 Provider（AGSX 或 PPIO）和对应密钥，然后启动：

```bash
uv sync
UV_CACHE_DIR=/tmp/testagent-uv-cache uv run testagent-sandbox-gateway
```

如果只交付 Sandbox 源码，可独立安装 Contracts、Client 和 Gateway：

```bash
pip install ./packages/sandbox-contracts ./packages/sandbox-client
pip install ./services/sandbox-gateway
```

正式 Agent 通常只安装前两个 Client 侧包；Gateway 在独立进程或容器运行。

默认开发凭据是：

```text
token:   demo-token
tenant:  demo-tenant
agent:   demo-agent
```

可以用环境变量覆盖，格式为多个逗号分隔的 `token|tenant|agent`：

```dotenv
GATEWAY_API_KEYS=agent-a-token|tenant-a|agent-a,agent-b-token|tenant-b|agent-b
```

`demo-token` 只用于本地演示，不能直接用于生产。

Agent 进程使用同一个 Token，但只需要 Gateway 地址，不需要 Provider 密钥：

```dotenv
SANDBOX_GATEWAY_URL=http://127.0.0.1:8787
SANDBOX_GATEWAY_API_KEY=<与 GATEWAY_API_KEYS 第一段一致的 Token>
```

经营简报的 PPTX 使用受控 Artifact Tool 渲染器，PDF 使用 Unicode TTF 字体。当前
POC 还需给 Gateway 配置本机路径：

```dotenv
ARTIFACT_TOOL_ROOT=/absolute/path/to/@oai/artifact-tool
# ARTIFACT_TOOL_NODE=/absolute/path/to/node
# BRIEFING_FONT_PATH=/absolute/path/to/unicode-font.ttf
```

`ARTIFACT_TOOL_ROOT` 是当前 POC 的部署依赖；正式发布前需要打包为可分发的渲染服务，
不能依赖开发机或 Codex 私有运行时路径。

健康检查：

```bash
curl http://127.0.0.1:8787/health
```

## 给另一个 Agent 接入

同步 SDK 示例：

```python
from sandbox_client import SandboxClient

with SandboxClient("http://127.0.0.1:8787", "demo-token") as sandbox:
    code = sandbox.execute_code(
        "print(sum(range(10)))",
        provider_preference="tencent-agsx",
    )
    print(code.status, code.result)

    briefing = sandbox.analyze_spreadsheet_file(
        "operations.csv",
        b"date,department,amount\n2026-08-01,Design,100\n",
        generate_briefing=True,
    )
    print(briefing.result, [item.name for item in briefing.artifacts])

    page = sandbox.browse_public_page("https://example.com")
    print(page.result["title"], page.receipt["cleanup"])
```

如果 Agent 本身是异步运行时，使用 `AsyncSandboxClient` 的同名方法即可。

项目内置的完整演示：

```bash
UV_CACHE_DIR=/tmp/testagent-uv-cache uv run python -m examples.gateway_client_demo
```

## 直接调用 HTTP

上传文件：

```bash
FILE_ID=$(curl -sS http://127.0.0.1:8787/v1/files \
  -H 'Authorization: Bearer demo-token' \
  -H 'Content-Type: application/json' \
  -d '{"name":"input.txt","media_type":"text/plain","content_base64":"aGVsbG8="}' \
  | python -c 'import json,sys; print(json.load(sys.stdin)["file_id"])')
```

创建一次代码执行：

```bash
curl -sS http://127.0.0.1:8787/v1/executions \
  -H 'Authorization: Bearer demo-token' \
  -H 'Idempotency-Key: demo-code-001' \
  -H 'Content-Type: application/json' \
  -d '{
    "task_type":"code",
    "source":"print(2 + 2)",
    "provider_preference":"tencent-agsx"
  }'
```

返回 `execution_id` 后轮询 `GET /v1/executions/{execution_id}`，直到
`succeeded`、`failed` 或 `cancelled`。成功结果中的 `receipt.cleanup.destroyed` 必须为
`true`；这条字段是演示沙箱闭环时最重要的清理证明。

## 与 Agent Loop 的连接方式

Agent Loop 只需要把 SDK 方法包装成工具：

```text
模型选择 execute_code / analyze_spreadsheet_file / browse_public_page
             ↓
工具函数调用 SandboxClient
             ↓
Gateway 返回结构化 ExecutionView
             ↓
工具把 result、artifacts、receipt.cleanup 放回模型上下文
```

模型不应直接拼接 Provider SDK 调用，也不应接触 `E2B_API_KEY`、`PPIO_API_KEY`。

## 真实 Provider 端到端验证

Gateway 的离线测试使用 Fake Provider；要验证“HTTP → Gateway → AGSX/PPIO → Receipt → 销毁”，
先确认 `.env` 中的 Provider 配置和余额，再显式允许一次云调用：

```bash
UV_CACHE_DIR=/tmp/testagent-uv-cache uv run python scripts/gateway_provider_e2e.py \
  --provider ppio-sandbox --task code --confirm-cloud
```

可选任务：`code`、`sales`、`spreadsheet`、`briefing`、`browser`。每次脚本只创建一个短时实例，并输出：

```text
provider_selected
execution_id
sandbox_id
status
receipt.cleanup.destroyed
```

报告会写入 `artifacts/gateway/e2e/`。本次已完成一轮 PPIO Code 验证：执行成功、耗时约
1.3 秒、`receipt.cleanup.destroyed=true`；随后按项目标签扫描 AGSX/PPIO，结果均为 `[]`。
脚本默认拒绝云调用，避免误触发费用。

## 重启恢复和孤儿扫描

Gateway 重启后，无法恢复原进程中的 Python/Browser 状态，因此会把本地未完成记录标为
`GATEWAY_RESTARTED`。远端清理只针对带有 `managed_by=lazyx-testagent` 标签的实例：

```bash
UV_CACHE_DIR=/tmp/testagent-uv-cache uv run python scripts/gateway_recovery.py \
  --max-age-seconds 600
```

只检查本地记录、不访问云端清理接口：

```bash
UV_CACHE_DIR=/tmp/testagent-uv-cache uv run python scripts/gateway_recovery.py \
  --skip-orphan-scan
```

V0 不会猜测或删除没有项目标签的实例。

## 当前边界与下一步

V0 是可运行的单机网关：SQLite、进程内 Token 映射、本地 Artifact 目录、线程池执行。
进入多人或生产环境前还需要：

1. 把 API Key 换成 KMS/密钥服务或 OIDC/JWT，并增加配额和审计日志。
2. 把 SQLite/本地 Artifact 换成 PostgreSQL/对象存储，增加过期回收和断点恢复。
3. 将任务队列换成可恢复的队列，处理进程重启、重复提交和 Provider 超时。
4. 对 `offline`、`vpc_restricted` 做真实网络策略和 DNS/Metadata 专项证明；不能仅凭配置字段宣称隔离。
5. 为 Browser 增加 URL allowlist、重定向复核、SSRF/DNS rebinding 防护和浏览器资源配额。

这些是 V0 之后的工程化工作，不影响其他 Agent 先用统一接口完成接入验证。
