# TestAgent 模块化架构与发布设计

## 目标

本仓库使用 Monorepo 提升联调效率，但 Sandbox 与 Web Capability 必须能独立构建、
测试、版本化、部署和下载。`apps/dev-agent` 只是开发测试台，正式 Agent 或其他人的
Agent 通过 SDK 和 HTTP API 使用能力服务，不依赖测试台源码。

## 依赖方向

```text
Dev Agent / Formal Agent / Other Agent
        │
        ├── sandbox_client ── sandbox_contracts ── HTTP ── Sandbox Gateway
        │                                                └── AGSX / PPIO
        │
        └── testagent_web_tools ─────────────── HTTP ── Web Capability
                                                         └── Tavily / Brave / Exa
```

服务端不得导入 `apps/dev-agent`。SDK 不持有 Provider 密钥，只持有服务地址和服务身份。

## 交付单元

| 单元 | 当前版本 | 交付形式 | 标签建议 |
| --- | --- | --- | --- |
| Sandbox Contracts | 0.1.0 | Python wheel/sdist | `sandbox-v0.1.0` |
| Sandbox Client | 0.1.0 | Python wheel/sdist | `sandbox-v0.1.0` |
| Sandbox Gateway | 0.1.0 | Python wheel + Docker | `sandbox-v0.1.0` |
| Web Capability | 0.1.0 | Rust service + Docker | `web-capability-v0.1.0` |
| Web Tools | 0.1.0 | Python wheel/sdist | 随 Web Capability 兼容版本发布 |
| Dev Agent | 0.1.0 | 开发示例 | 不作为生产依赖 |

## 本地开发

安装所有 Python Workspace 包：

```bash
uv sync --frozen
uv run pytest
```

启动两个服务：

```bash
cp .env.example .env
cp services/web-capability/.env.example services/web-capability/.env
docker compose -f deploy/compose.yaml up --build
```

随后运行测试 Agent：

```bash
uv run testagent
```

## 独立安装

Sandbox SDK：

```bash
pip install ./packages/sandbox-contracts ./packages/sandbox-client
```

Sandbox Gateway：

```bash
pip install ./packages/sandbox-contracts ./services/sandbox-gateway
testagent-sandbox-gateway
```

Web Tools：

```bash
pip install ./packages/web-capability-tools
```

Web Capability：

```bash
cargo run --release --manifest-path services/web-capability/Cargo.toml
```

## API 契约

- `contracts/sandbox-openapi.yaml`
- `contracts/web-capability-openapi.yaml`

客户端与服务端变更必须先判断是否破坏契约。破坏兼容性的字段删除、含义变化或路径变化
需要提升主版本；新增可选字段可提升次版本。

## GitHub CI 与发布

- Python 路径变化触发 Workspace 测试和五个 Python 包构建。
- Rust 路径变化触发 fmt、clippy 和全量测试。
- 两个 Dockerfile 分别执行容器构建检查。
- `sandbox-v*` 标签发布 Sandbox wheels 和 Gateway 镜像。
- `web-capability-v*` 标签发布 Web Capability 镜像和 Web Tools wheel/sdist。
- 真实 AGSX、PPIO、Tavily、Brave、Exa 调用不在普通 PR 中自动执行，避免费用和密钥风险。

## 生产边界

Sandbox Gateway 目前仍使用 SQLite、本地 Artifact、进程内 Token 和线程池，适合 POC/
内部低风险使用；生产前需要正式身份、配额、审计、持久队列、数据库和对象存储。

Web Capability 默认只监听本机。需要跨机器共享时，应先增加服务认证、限流和租户配额，
并放在 TLS 入口或私网服务发现之后，不能直接把无认证端口暴露到公网。

## 何时拆分 GitHub 仓库

当前继续保留 Monorepo。只有当独立团队、独立权限、不同开源策略或发布节奏明显分离时，
再把 `services/sandbox-gateway + packages/sandbox-*` 与
`services/web-capability + packages/web-capability-tools` 拆为独立仓库。
