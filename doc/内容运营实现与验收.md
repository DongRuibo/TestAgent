# 内容运营实现与验收

本批基于 `codex/personal-agent-monorepo` 的实际工作区增量开发。初始 HEAD 为
`addc75e80fa641a4e6a3f3afec353a11aa9f10ec`，工作区原有大量未提交能力；本批没有提交、
推送、创建 PR、合并或部署。代码完成与真实业务验收分开记录。

## 交付范围

保留原有运营目标、真实研究能力、Markdown 周计划及修订历史，在已保存计划之后增加：

1. 选择一个具体计划版本中的选题，复用目标、研究读取回执和用户素材生成单条图文。
2. 保存标题、正文、标签、图片说明、事实原句及来源；模型回复不能代替保存回执。
3. 编辑或仅重新生成该条内容，创建新版本；批准绑定已保存正文和图片哈希，修改后重新审核。
4. 先保存业务执行意图，再创建关联 RPA Job。刷新与查询只对账原任务，不重新保存。
5. 保存后重新打开草稿，核验标题、正文、实际图片数量和标签；不执行最终发布。
6. 结果不明进入 `needs_review`。人工确认存在单独记为 `manually_confirmed`，不冒充机器核验；
   人工确认未保存时另存待审核新版本，不重放原任务。

来源等级由宿主成功取数回执建立。只有搜索结果不能称为已读取正文；引用结构通过不等于
事实语义正确。标签当前为正文中的 `#话题` 文字，完整读回不证明平台已将它识别为原生话题组件。

## 三条演示路径

先按根 README 配置并启动本地 Web；真实模型调用、研究费用和平台账号操作需有单独授权。

### 正常完成

1. 在同一对话确认运营目标，完成已授权研究并保存新版周计划。
2. 在“选择一条制作小红书图文”中选择选题，填写本条要求，生成候选。
3. 核对来源、正文和素材缺口，上传或选择图片，点击“保存修改和图片为新版本”。
4. 点击“批准已保存的此版本”，再明确点击“确认启动 RPA 保存草稿”。
5. 查看逐字段核验结果并刷新页面，确认恢复的是原内容版本和原执行记录。

目标确认和周计划交付都不代表正文获批；本流程始终不执行最终发布。

### 人工修改

1. 编辑某条标题、正文、标签或图片，保存新版本，检查旧版仍存在。
2. 确认新版本回到待审核，旧批准不能执行。
3. 只重新生成此条时填写具体意见，检查其他条目未变、研究未重新取数。

### 故障恢复

离线评测 R02/R03 注入 Job 创建后回调前中断、草稿完成后业务回写失败。
重建服务后只查询原 Job，检查业务与 Job 的 execution ID 一致，提交数仍为1。
R01 验证超时后进入待核验以及人工确认未保存后的新版本；R06 验证正文读回错误不误报成功，
人工确认存在也只记录人工结论。正式账号不要用故意崩溃作为首轮演示。
