# 宿主提供目标工具时的交接

此参考仅用于提供 `save_operation_goal`、`load_operation_goal` 的 TestAgent 宿主；可移植业务契约仍见 [goal-schema.md](goal-schema.md)。不支持这些工具的宿主继续用业务语言交付目标。

用户要求保存、交接，或宿主标记当前为目标工作流任务时，用 `save_operation_goal` 保存企业名称、企业背景和结构化 `operation_goal`。宿主已传入企业档案时沿用该快照，只追问本期缺失信息，不要求重复上传。机器字段以 Tool Schema 为准：

- `summary`、`business_direction`、`target_users`：本周期目标摘要、业务方向和目标用户。
- `period.start/end`：用户确定的日期；不猜测缺失周期。
- `metrics`：只列适用指标，每项包含 `name`、`definition`、`baseline`、`target`、`data_source`、`review_frequency`；区间可用文字保留，未知基线用 null，不填零。
- `resources`、`constraints`、`budget_statement`、`evidence`、`assumptions`、`risks`：保留人员产能、约束、预算陈述、依据和不确定性，不把用户报告升级为已核验事实。

组合模式只调用一次 `save_operation_goal`：`operation_goal` 保存月目标，顶层 `weekly_goal` 保存简单周目标，使用相同目标字段，另加 `contribution` 说明与月目标的关系，且最多三个指标。单周期模式省略 `weekly_goal`。两部分共同纳入版本和哈希；在展示两部分并说明确认范围后，用户回复“确认这版目标”或“确认第 N 版目标”确认整版。不能把周目标只写在回复中而漏存，也不把周目标另存为月目标的替换版本。

工具生成目标 ID、版本和哈希，草案默认为待确认。不要向保存工具传入确认状态、版本、ID 或哈希。保存后用普通 Markdown 展示目标，提示用户回复“确认这版目标”或“确认第 N 版目标”。宿主核验真实用户消息、当前版本和哈希后记录确认；模型自行说“已确认”不能代替该记录，“好的”等模糊回复不执行确认。目标确认仍不代表预算审批或研究执行授权。

修改已保存目标时，先 `load_operation_goal` 读取用户指定或宿主绑定的 `goal_artifact_path`，然后在保存时传入 `previous_goal_artifact_path`。工具保存同一目标的新版本，保留旧版本；新版本不沿用原确认。不要为绕过版本检查，把修改另存成毫无关联的新目标。

Web 中用普通文本说明核心目标、依据、资源、预算、风险和待确认事项；补充、修改和确认都使用聊天输入框。历史目标作为只读文本展示，不要求用户复制文件路径。后续 14.2 由宿主传递绑定文件，宿主先说明费用边界，再等待用户明确回复“同意费用并启动本次研究”，不得在目标 Skill 自动继续。任务侧栏只显示进度，不承载操作或详细结果。没有该界面的其他宿主仍可交付文件路径。

保存参数校验失败时，根据错误字段修正后重试本地保存（最多两次尝试，只能成功保存一次），不重新制定目标，也不要求用户先确认未保存草案。只有拿到成功的版本回执后才请求确认。
