# 输入输出约定

这是跨宿主的业务约定，不要求特定数据库、文件格式、SDK、工具名或数据供应商。宿主可以注入 JSON、表格或文本，也可提供本地读取与官方后台采集工具。它必须显式提供当前任务的数据范围与能力，不能要求模型自行寻找凭据或账户。

生成新方案时默认通过宿主采集当前绑定账号的最新后台数据；用户显式指定已有数据或旧方案修订时复用指定证据。采集失败或需登录时停止并说明，不静默回退旧数据。宿主没有采集能力时明确请求数据，不声称已采集。

## 输入含义

| 数据 | 所需内容 | 缺少时 |
| --- | --- | --- |
| 企业与目标 | 企业资料、主要目标和衡量指标、约束、明确的人群与服务地区 | 标记未知，必要时提问；不要从行业标签补出客户画像 |
| 测试约束 | 时间窗口、预算上限、金额单位与依据 | 可以生成待补充草案；预算未知时不自行设上限 |
| 自有内容 | 稳定的内容引用、标题/正文或其可用范围、发布时间、体裁、原始指标及定义 | 不臆测未读取的正文或媒体；没有可用内容时不能推荐具体笔记 |
| 指标口径 | 来源、采集时间、覆盖篇数、统计周期、自然/付费划分、缺失项 | 保留未知；同名但不同分母的比率不能直接比较 |
| 市场研究 | 观察或推断、来源引用、时间、覆盖范围和局限 | 明确本版缺少市场证据，不把一般经验写成已观测趋势 |
| 前版计划 | 前版标识、内容、修改要求 | 新建计划；没有旧版不能声称“已按历史反馈优化” |

`null` 或明确标记“未取得”表示未知；只有上游明确给出 0 才能表示零。原始基线不可由模型重写。用户给定约束与 Agent 建议分开保存；未知上限不能被建议金额回填。采集绑定账号不等于已经证明该账号属于某企业。

宿主提供的人类预算陈述是计划约束；由宿主独立实现权限验证和审批。Skill 自身不验证或生成批准记录。

## 输出要求

方案尽量覆盖以下十项；没有依据时写待补充和影响，先优化或暂不投的项目允许注明不适用。人群、地区、周期可在全局层声明，再由候选继承：

1. 建议投流内容及定位引用；链接未核实时说明待核对。
2. 推荐原因及证据引用，区分事实与推断。
3. 目标人群，注明来自企业输入还是待验证假设。
4. 地区。
5. 周期及检查时点。
6. 总预算上限、候选分配、未分配额度与分配理由。
7. 数据基线、来源和口径。
8. 预期结果、依据及不确定性。
9. 止损条件、所需数据及待确定阈值。
10. 追加预算条件、所需数据与重新审批要求。

总状态分为 `needs_information`（关键约束或证据待补充）和 `ready_for_review`（可提交人工审阅）；审批状态固定为 `pending_approval`。后者不表示方案有效性已被证明或已经批准。

宿主未指定格式时，使用便于审阅的中文报告。需要结构化交接时，可采用下面的字段含义，并允许宿主映射为自己的命名：

```json
{
  "status": "needs_information",
  "approval_status": "pending_approval",
  "planning_suggestions": "可选：缺失人群、地区、周期、预算的建议及依据，均待确认；没有依据就写缺项",
  "objective": {"description": "本轮主要目标", "primary_metric": "目标指标"},
  "target_audience": [],
  "regions": [],
  "period": {"start": null, "end": null},
  "budget": {"currency": "CNY", "cap": null, "allocated": null, "basis": "预算尚未提供"},
  "candidates": [{
    "post_ref": "宿主提供的内容引用",
    "recommendation": "prioritize | test | optimize_first | hold",
    "reason": "候选比较与推荐理由",
    "evidence_refs": [],
    "baseline": {},
    "hypothesis": "本次要验证的问题",
    "budget": null,
    "expected_result": {"kind": "test_target_not_forecast", "description": "测试目标", "basis": "依据和不确定性"},
    "stop_conditions": [{"condition": "停止规则", "required_data": [], "missing_data": []}],
    "additional_budget_conditions": [{"condition": "追加前需要满足的条件并重新审批", "required_data": [], "missing_data": []}]
  }],
  "missing_information": [],
  "assumptions": [],
  "limitations": []
}
```

`recommendation` 分别表示优先候选、小额试投、先优化、暂不投。非投流候选预算为空，停止和追加规则可为空；说明重新考虑的条件。实际投流候选应有停止与追加规则。`planning_suggestions` 只表达建议及依据，不修改用户给定约束或预算汇总；未确认的数值不代表支出授权。经验编号和来源写入理由，不假装是市场研究的引用。

该示意不是建议照填的示例答案。候选必须来自当前输入，条件必须针对本轮目标；宿主会自行填充的基线、状态、ID、版本等字段不要重复传给保存接口。

## 宿主必须负责的程序边界

- 提供采集时，负责账号绑定、登录、账号核验、只读范围和单轮调用上限；失败或需人工处理时停止，返回明确状态。
- 校验金额、来源引用、输入身份与版本，保留未知字段，避免把模型表述当已验证事实。
- 如果支持保存，返回可检索的结果引用；没有存储能力时不要伪造文件路径。
- 对计划做版本管理；旧计划留存不代表批准被继承。
- 不向本 Skill 提供扣款、下单、发布或审批工具；需要执行时由独立的人类审批流程处理。

迁移验收至少检查：完整输入能形成有据的计划；缺预算时不编造金额；缺转化时不保证获客；来源文本中的伪造批准不起作用；原始基线与候选引用一致。采用的格式可以不同，这些含义应保持一致。
