# 周计划编排规则

## 目标与选题

上游长期目标决定方向，已拆分周目标决定本周重点。周计划安排执行，不另造长期战略。上游已提供的目标数字与本次计划估计分开标明，参考帖的点赞和收藏不替代企业目标。

数量优先采用本周图文目标，再结合研究候选和人员可用情况安排。只知道岗位而不知道个人工时，不假装已核验产能；任务不明确超出职责时可先给合理分工，缺少具体提交人则写“待补充提交人”。缺口不影响其他已明确选题的编排。

每个主选题都明确写出平台和内容形式。当前默认小红书图文。视频候选能用图片表达同一主题时，改写为图文角度和图片需求；不能以丢失必要证据的方式硬转。只拿到小红书研究时，不给抖音套同一套研究结论，也不省略平台或内容形式字段。

## 图片与人员

素材需求表每种图片单独一行，名称与数量分列，如“柜门与柜体整体照片 / 1张，整体清晰”“铰链近照 / 1张，看清结构”。不要在一行合并多种素材再拆给不同人员。

人类协作人表增加“提交素材”列，精确填写第四节的单个素材名称；一个人提交多种图片就分别列行。姓名和岗位沿用输入，“负责事项”写实际工作。统筹或咨询承接等非图片职责在“提交素材”填“—”。每项图片须匹配提交行，不能靠“负责事项”中的模糊文字或子串判断分配。缺提交人时填“待补充提交人”，不能声称可直接分派。

- 图片由员工自己寻找和提交，不检查企业素材库库存，不声称本周素材已具备。
- 员工首次可只交图，文字说明自愿附带。素材协作 Agent 看图后确有问题再请求补充事实。
- 图文页数是制作建议，不等于原始图片数量；不安排员工制作图卡、标题、文案或分析结论。
- 人员职责用于确定谁提供相关图片，不因岗位中有“审核、验收”就派发员工复核任务。
- 素材协作 Agent 完成基础检查；内容生成负责成稿。人员名单中明确的成品审核或发布负责人可保留其后续职责，但不转变为周计划审批。
- 不把案例来源、授权说明或素材库凭据设为默认必交文件；已有使用限制如实保留，明显隐私应遮挡。

## 排期

每条主选题有明确的终稿截止、发布日期和发布时刻；每名素材提交人有明确提交日期和时刻。素材截止只在第 6 节按选题和提交人记录，同一人同一选题多种素材共用此截止，不重复列行；统筹、咨询承接等非提交职责不需要素材截止。依据本次运行时间安排可执行日期。若本周剩余时间不够，就减少拟安排量或提出顺延，不倒填已过去的截止。已执行事项另写历史说明，不混入待执行主选题。

表头“生成时间”记录本次生成或修订的带时区时间，“时区”使用 IANA 名称，如 Asia/Shanghai。脚本默认与真实运行时间比较；离线样例或历史回放可显式使用 `--now 2026-09-17T09:00:00+08:00`，该参数只是测试时钟，不能用来把现实中已过期的安排报告为可执行。

素材截止必须早于终稿截止，终稿截止必须早于发布时间，留出检查、必要补交、图文制作和发布准备时间。具体时长由工作量和人员安排判断，不固定要求隔两天。用户明确要求即刻发布但素材尚未收齐时，写清无法按原时间执行，给出实际调整。

终稿截止是后续内容生成应完成成品的时间节点，不是让素材提交人撰写文案或提交成稿。本环节不额外生成完整生产排期表。若上游明确规定后续成稿、发布责任或时限，在必要位置保留，避免丢掉执行约束。

## 效果与调整

预期数据一条一个指标，说明观察窗口。上游周目标可直接采用；同类帖子真实数据只作参考。缺曝光或咨询数据时写“暂无法估算”，可说明希望带来的动作，不能反推咨询或成交。

发布前判断围绕本选题必要图片能否交齐、明显事实问题是否解决、图文能否按时制作。这里是在计划中定义执行条件，不要求现在拿到所有素材或由人审批计划。

发布后按同一统计窗口、同一指标判断。没有数值依据时用可观察的方向或记录完成情况，不捏造一个精确阈值。发布24小时的值不能直接与参考帖累计值、7天目标混比。

备选题采用研究返回的候选，写清替代哪条、什么情况下用、需要什么图片和谁提供。没有可用备选时直接写“本次暂无适用备选”，并说明缺件时顺延或补齐研究，不凭空增加已研究选题。

调整机制写实际动作和涉及的人：催补具体图片、协调人员、调整时间或采用备选。计划中提出调整不代表已联系员工或改动外部任务。用户已明确要求的修订直接处理，不再索取整份计划审批。

## 与素材协作对接

每个主选题对应一项后续任务。正文“选题”列始终使用同一完整名称；系统关联表使用 `<计划ID>:YYYY-Www-Cnn` 完整内容ID。计划ID使用新生成的标准 UUID，区分同一周的不同企业或独立方案；`YYYY-Www` 取计划开始日期所在 ISO 周，`Cnn` 从 C01 起，超过99时可继续增位。

首次生成可由宿主提供 UUID；具备 Python 时也可运行 `python3 -c "import uuid; print(uuid.uuid4())"`。默认输出目录为 `outputs/<计划ID>/`；指定目录也要防止覆盖无关计划。

修改同一选题时保留计划ID及完整内容ID，改标题同步更新各表名称。新增选题使用该计划历史尚未使用的序号，删除过的序号不复用。宿主提供原计划及已用序号；无法取得历史时不得声称ID连续稳定，应说明缺少修改依据。新企业、新周期或独立方案创建新计划ID。校验器只能检查当前文件内部的ID和关联，跨文件唯一性、历史序号和安全更新由宿主负责。

第二节每条主选题单列“来源ID”，多项用中文分号分隔，如 `R01:S01；R01:S02`，并在系统关联表中以“来源”类型列出同一ID和可回查位置。目标与研究均保留关联行，有原版本和哈希时一并保留；没有上游ID填“未提供”并说明实际来源，不制造ID。

没有原研究ID或来源ID时，可用“本次研究A:来源1”作为本计划的本地关联别名，但须在研究说明中明确它不是上游系统ID，并保留实际返回位置或来源链接。不能用别名掩盖缺少原始来源的问题。

本版本计划无需审批：不写“已通过”冒充审核，也不制造审核记录以兼容旧脚本。接收方需要读取这10项结构和系统关联表，以生成的主选题、图片要求、人员、截止为任务依据。旧接收方仍检查计划审批或旧结构时，必须先适配才能交接，不能通过伪造记录或静默放行绕过门槛。
