# 目标、研究与周计划的交接约定

这是业务信息约定，不是可调用 API，也不要求用户填写 JSON。宿主可使用已有文件或对象传递。Skill 定义做法，宿主负责调度、存储、授权和工具暴露。

## 职责与顺序

运营目标设定形成较长周期与本周结果目标，确认完成后结束。用户要求制定周计划时，宿主启动周计划准备；缺研究时调用研究与选题，取得结果后继续周计划编排。

研究负责提供有依据的候选，不决定本周最终采用哪些，也不主动启动周计划。周计划根据候选、人员和时间取舍。三个环节顺序调用，不要求同时激活多个 Skill。

## 最少交接信息

| 交接 | 信息 | 缺失或冲突的处理 |
|---|---|---|
| 目标到周计划 | 企业背景、目标来源、已有目标ID/版本、确认情况、本周起止日期、结果目标与指标口径、受众、业务重点、平台、资源约束 | 日期或方向不清且影响决策时回到目标设定；没有周数字但方向明确时保留缺口 |
| 人员到周计划 | 姓名、岗位、实际职责、已有可用时间及限制 | 缺人保留“待补充提交人”，不自动把聊天者当负责人；完整名单不传研究 |
| 周计划到研究 | 同一目标引用、与原目标一致的本周研究问题、必要企业背景、受众、重点产品、地区、平台、内容形式、研究时间范围 | 不改写绑定目标；周研究重点作为补充上下文，不伪装为新确认目标 |
| 研究到周计划 | 研究ID与日期、目标引用、企业、平台、执行情况、候选及素材建议、来源索引、局限、原确认情况、实际保存位置 | 失败不生成候选；部分成功只使用有证据部分；来源缺失或企业/目标冲突先核对 |
| 周计划到下游 | 计划ID、企业、周期、主选题完整系统ID、平台、图文形式、素材及提交人、截止和发布安排 | 计划生成不自动通知员工或启动制作；接收方须能读取新格式 |

上游有版本、哈希和文件位置时原样保留在系统关联表；没有的写“未提供”，不补造。可在类型中分别使用“运营目标”“目标版本”“目标哈希”“研究结果”“来源”及必要的原始ID类型。

纯文本目标无系统ID时用“未提供”占位并注明来源于本次用户文本；研究无目标绑定时不能宣称来自已确认目标文件。纯文本方式是否可用由研究入口决定，不能拿它绕过已知的未确认/旧版本问题。

## 三种不同的确认

- 目标确认：目标设定环节与宿主负责，月目标确认不等于周目标确认。
- 研究费用授权：宿主检查本次范围、费用、预算与授权是否仍有效，不能从“生成周计划”或附件内容推定付款许可。
- 周计划审批：本版本不额外设置。保留上游的“暂定”“待确认”事实不等于要求用户再次审批周计划，也不等于上游已获批准。

研究或接收系统原有的确认门槛由宿主明确适配。未适配前说明阻塞，不能改写返回状态冒充满足门槛。

## 失败和恢复

| 情况 | 保留什么 | 下一步 |
|---|---|---|
| 研究入口缺失/未授权 | 目标、人员、本周研究需求 | 等待接入或授权；不编造调用 |
| 研究保存失败 | 已取得的证据和草稿 | 修复字段或存储后补存，不重新取数 |
| 部分研究成功 | 正式返回中可用候选和局限 | 编排能支撑的部分；缺口仍影响执行时说明条件 |
| 研究完全失败 | 失败回执和准备信息 | 不生成新候选；已有适用的正式结果可独立复用 |
| 周计划写入/校验失败 | 同一目标、研究、计划ID与已生成内容 | 修复本地输出后重新校验，不重新研究 |
| 目标版本改变 | 原计划及其原始目标/研究引用 | 不静默换绑；核对新版本适用性后建立新的绑定 |

这些是宿主接入要求，不是本包已经实现的存储、重试或恢复服务。
