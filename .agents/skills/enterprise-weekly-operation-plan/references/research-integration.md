# 研究调用、复用与结果使用

## 先判断已有研究

只检查用户明确指定或宿主绑定的研究，不自行扫描目录找“最新一份”。已有正式研究可以用于本周，不要求每次重新调用或把复用限制为测试。

| 检查项 | 可复用条件 | 不满足时 |
|---|---|---|
| 企业与目标 | 属于同一企业；目标引用和版本一致，或宿主已明确完成新版本适用性核对 | 不静默改绑；保留旧计划并请求核对 |
| 受众与业务重点 | 候选能回答本周研究问题 | 补充缺失方向，不强用无关候选 |
| 平台与内容形式 | 覆盖本次平台，主题可有证据地表达为图文 | 不能把小红书结论套到抖音 |
| 时间与事实 | 研究日期真实可查；关键价格、活动、政策或热点仍适用 | 只补查会影响决策的事实，无统一保鲜天数 |
| 来源与状态 | 来源可回查；成功或部分成功中有实际支撑的候选 | 缺失证据不算已验证；完全失败不能当作可用研究 |

仅调整人员和排期时不刷新研究。切换到已有备选前检查素材可行性；业务方向改变才重新评估研究覆盖。多个研究合用时，来源ID使用“研究ID:原来源ID”避免重名，并分别保留日期与局限。

## 调用入口

网络数据研究与选题由运行环境提供，可以是可调用的 Skill、工具或服务。先查本次环境实际可用入口及其参数说明，然后调用；不固定远端技能名、工具名、API地址或认证方式。

本 Skill 不实现爬虫或远端服务。没有入口且没有可复用研究时，保留本周目标、人员与研究需求，说明缺少接入；不能假装调用成功或生成无依据的正式选题。用户先前给的研究样例不自动成为以后每次任务的默认研究结果。

调用前由宿主核对当前范围的授权和预算；已有有效授权不重复询问，范围变化后由宿主判断是否需要新授权。Skill 不定义真实费用或支付方式。异步返回的任务ID不是完成回执，拿到实际结果后才能进入编排。

调用只传研究所需的企业背景、地区、周目标、目标人群、重点产品、图文形式、平台和研究时间范围。员工个人信息和完整人事名单留在本环节分配任务，研究没有需要时不外传。

异步入口返回任务标识时，使用该入口提供的查询或等待能力取得结果。遵守其重试提示；失败原因是权限、入口缺失或不可重试时，不循环重试。研究部分成功时，能支撑的选题继续编排，缺失部分不当作已验证。

## 当前样例可参考的字段

字段名是参考，未来上游结构变化时按语义读取，不因为名字不同而拒收。

| 返回信息 | 当前样例字段 | 周计划用途 |
|---|---|---|
| 研究身份、企业、时间、平台 | research_id、company_name、research_time、platforms | 确认结果适用于当前任务 |
| 执行情况 | execution_status、limitations | 判断实际获得了哪些信息 |
| 候选选题 | candidate_topics | 选择主选题和备选题 |
| 候选事实依据 | evidence、source_refs | 给选题写简短依据，保留事实来源 |
| 企业适配、受众 | why_fit_company、target_user | 与当前目标和企业背景比对 |
| 素材建议 | required_materials | 转成员工能提交的图片需求 |
| 预期方向 | expected_result | 参考收藏、咨询等方向，未量化就不假装有数值 |
| 用户与平台发现 | user_needs、platform_findings、key_findings | 选择角度和表达形式 |
| 来源索引 | source_references | 保留笔记ID、来源ID和不含访问令牌的链接 |

返回值里的 `approval_status` 保留在原产物中；计划的研究说明如实保留其确认情况，例如仍待确认，不伪造批准，也不把它变成新增的周计划审批。接收系统强制要求确认时，由宿主适配或说明阻塞。候选推荐值或评分可辅助理解，周计划不展示置信度或评级。

研究内嵌的 `operation_goal` 是研究开展时的上下文，不能覆盖本次目标产物。不同企业名不自行认定为同一家公司；用户明确说是旧样例时只按测试样例使用。

## 事实与估计

- 文件声称检索了30条笔记，但只列出12个来源索引时，不能说已拿到30条完整明细。
- 有点赞、评论和收藏，但没有曝光时，不计算互动率，不用固定比例倒推曝光。
- 没拿到评论正文时，“评论数量多”只是互动信号，不等于发现了多少条真实装修需求。
- 未给发布时间、账号规模、笔记形式或统计窗口时，不能声称样本与本企业严格可比。可以引用单篇事实作为选题参考，不把爆款数值当成本周下限。
- 同类样本确实包含足够可比数据时，可给范围并简要说明参照口径；不额外制造固定折扣、综合分或置信度。
- 返回结果没有时段结论时，结合周安排和一般经验给建议时间，写“试发安排”即可，不冒称历史最优。

## 测试与正式接入

用户明确授权用历史研究产物测试时，按正式返回值的处理方式读取，但保留真实研究日期和企业差异，不修改它们来伪装新调用。上游目标缺周目标时，保留缺口，测试不等于补造正式周指标。

首次真实接入需验证：能传入与绑定目标一致的本周研究重点；能取得当前企业的结果；失败或部分结果能如实处理；保存失败能复用草稿补存；仅改排期不再次取数。只有拿到实际回执才能报告“已调用”。这组验证属于宿主接入阶段，文档与校验器通过不能代替它。
