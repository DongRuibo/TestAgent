## Recovery的实际含义

复用 `evals/recovery_analysis.py`，保留原命名，同时收紧解释：

| 分类 | 修复后 | 实际依据 |
|---|---:|---|
| 原脚本的automatic_business_recovery | 21/45 | 原契约通过且持久执行最终为draft_saved |
| safe_human_handoff | 12/45 | 3次manually_confirmed、3次reviewed_not_saved、6次needs_review |
| safe_stop | 12/45 | 故障处置契约通过且没有外部写执行 |
| unsafe_reporting | 0/45 | 恢复集合内未观察到无证据完成声明 |

21次中存在测试脚本显式调用 `reconcile_content_draft`、再次保存或重放请求的路径。该分类没有独立统计触发者、人工救援和完整无人干预区间，因此不能称为“无人干预自动恢复率46.7%”。12次转人工同时包含已处理和仍等待的任务，也不能称为12次人工救援已经解决。

修复后另有45条明确的持久保存意图，状态为：draft_saved 27、manually_confirmed 6、reviewed_not_saved 3、needs_review 9。其中27条取得原Job读回或合成评分器投影的核验结果。**这45条保存意图与45次恢复场景不是同一集合**；27/45是合成故障矩阵内的核验结果分布，不是生产自动完成率。

## 四类指标的公式和分母

先按来源和目标阶段分组，再计算率。正常任务、正确拒绝、故障注入与历史旧库不混为同一业务总体。

| 指标 | 计算与分母 |
|---|---|
| 端到端耗时 | 宿主最终判定时间−任务受理时间；必须绑定同一个逻辑任务 |
| Agent阶段 | 明确的Agent.run跨度；历史完整agent_run/agent_receipt配对后求各次duration_ms之和，标记为agent_active，不冒充业务墙钟时间 |
| RPA执行 | finished_at−started_at；排队为started_at−created_at |
| 浏览器读回 | 同一Robot XML内verifying_draft开始至最后实际执行的业务关键字结束；包含轮询/等待，不包含NOT RUN和teardown |
| 宿主二次核验 | 独立query_verified_draft/CompletionContract核验起止；缺失不从其他阶段差额反推 |
| P50/P95 | nearest-rank：ceil(p×N)，按来源、阶段、终态及原契约判分分组；同时输出有效与缺失样本数 |
| 自动完成率 | 宿主核验完成且能证明无异常人工救援的任务数/同目标任务总数；混合目标、总体未知或触发者不明保持null |
| 异常人工介入率 | 执行异常后需额外人工解决的任务数/同目标任务总数；正常审批不进入分子 |
| Job成功率 | succeeded唯一Job数/全部已创建唯一Job数；仍运行或排队不作为成功 |
| 草稿保存核验结果率 | 原执行/Job/审核版本一致且完整读回通过的保存意图数/明确已受理的保存意图数；结果不明保留人工核验状态 |
| 读回核验通过率 | 完整读回通过数/确实进入读回核验的Job数；另列完整核验通过数/全部Job，避免条件分母掩盖未核验 |
| 重复执行 | 按execution_id统计额外唯一Job；请求重放和额外平台保存副作用另列，没有独立副作用证据不填0 |

正常人工审批不计失败或异常救援。`manually_confirmed`不升级为机器完整核验，`reviewed_not_saved`不记保存成功，`needs_review`不记自动完成。没有实际取消记录时只报告观察到0条取消，不能推导生产取消率为0。

## 不可测项及最小埋点建议

以下仅为方案，未实施任何生产修改：

| 不可测项 | 缺失字段/证据 | 最小方案 |
|---|---|---|
| 完整端到端耗时 | 稳定逻辑任务与执行/Job映射、task_accepted_at、task_terminal_at | 业务入口和最终宿主结论各记录一条关联现有execution_id/job_id的日志事件 |
| 独立宿主核验耗时 | verification_started_at、verification_finished_at | 在现有核验调用前后记录计时，不改业务判定 |
| 无人干预自动完成/异常救援率 | post_fault_trigger_actor、human_action_kind、完整观察覆盖 | 区分正常审批、异常救援、人工核验和系统对账；无记录保持未知 |
| 真实平台保存率 | 已授权真实平台来源、原执行完整读回链 | 真实平台运行需另外授权；本任务不调用 |
| Robot重复外部保存次数 | 平台侧操作证据/独立副作用账本 | 保留实际保存操作证据，不以Job数量或点击数量代替 |
| 全部历史业务/浏览器任务总体 | 统一任务账本、缺失中断记录与无Job尝试数量 | 本轮仅报告明确来源的观察分母，不从残存记录外推 |

所有这些指标保持null或明确缺失计数，不填漂亮数字。正常审批记录只说明某步骤发生，不证明存在异常人工救援。

## 可用于简历的五组数字

1. 构建50个固定离线场景，每场景重复3次，新版执行契约150/150通过，覆盖正确拒绝、业务状态及故障处置。
2. 通过宿主完成核验，将固定合成故障集的假完成探针由3/9降至0/9。
3. 基于独立副作用账本，在30次定向合成探针中未观察到重复保存。
4. 在36次禁止执行合成探针中未观察到未审核RPA提交。
5. 45次合成恢复场景均满足故障处置契约，其中21次以核验保存结束、12次进入或记录人工处置、12次安全停止。

前三类率不能写成真实模型/真实平台/生产可靠性；第五条不能写成自动恢复100%或无人干预恢复46.7%。目前不推荐把少量故障矩阵耗时、3/4候选机械完成或4/11模拟平台Job分布写成生产性能与完成率。
